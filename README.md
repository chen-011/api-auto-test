# 接口自动化测试作品集

软件测试实习求职项目仓库。两个项目，记录从「练习场」到「真实业务链路」的实践过程。

## 📌 主项目：电商订单系统 · 接口自动化测试

> 目录：`ecommerce-api-test/`

被测对象是一个模拟真实电商业务的订单服务（登录鉴权 → 商品查询 → 下单 → 库存扣减 → 满减计算 → 订单查询），使用 Python 标准库实现，零第三方依赖即可运行。

**技术栈：** Python · pytest · requests · CSV 数据驱动 · 多线程并发

**核心数据：**

| 指标 | 结果 |
|---|---|
| 用例数量 | 32 条（21 条主测试集 + 11 条数据驱动） |
| 覆盖场景 | 6 类：登录鉴权 / 下单正常流 / 参数异常 / 满减边界 / 并发超卖 / 重复提交幂等 |
| 发现缺陷 | 4 个，全部定位到代码根因 |
| 回归结果 | 缺陷版 4 failed → 修复版 32 passed |

**发现的 4 个缺陷：**

1. **并发超卖**（严重）— 库存 5 件，10 个请求同时抢购，成功下单 10 单，库存被扣成负数。根因：先查库存、后扣库存，两步之间无锁保护。
2. **满减门槛差一错误** — 满 500 减 50，正好 500 元不减。根因：判断写成 `> 500`，应为 `>= 500`。
3. **重复提交生成两笔订单** — 同一 `request_id` 提交两次产生两笔订单、库存扣两次。根因：服务端无幂等校验。
4. **库存扣减无二次校验** — 与缺陷 1 同源，并发下库存变负。

**运行方式：**

```bash
cd ecommerce-api-test
pip install -r requirements.txt

# 测「有缺陷版」，应看到 4 条失败
python -m pytest -v

# 测「修复版」，应看到 32 条全部通过
MOCK_VERSION=fixed python -m pytest -v
```

## 📁 早期练习：httpbin 接口测试

> 目录：`httpbin-demo/`

基于公开 API（httpbin.org）的入门练习，用 requests + pytest 验证 GET / POST 请求、参数传递、状态码与响应断言，并用 CSV 做数据驱动。

这个项目用于熟悉 HTTP 协议与 requests 用法，业务深度有限，保留作为学习记录。

## 技术要点速览

- **用例独立性**：pytest fixture 每条用例前重置数据，失败可复现、互不污染
- **数据驱动**：用例写在 `cases.csv`，新增用例零改代码
- **并发测试**：`ThreadPoolExecutor` 模拟多用户抢购，暴露单线程测不出的竞态缺陷
- **缺陷闭环**：提交缺陷时记录复现步骤、预期 / 实际、影响范围，修复后回归验证
